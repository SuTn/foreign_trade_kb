## 六、深度排查记录 (2026-08-09, 真实 WhatsApp 联调)

实机联调发现并修复 3 个**根因级**问题 (此前采集器"心跳正常但 0 同步"):

1. **ReadOnlyCDP 同步调用异步 CDPSession.send** — 所有 CDP 调用返回未 await 的 coroutine 被丢弃, 从未真正执行。已全部改为 async + await (readonly_cdp.py / scanner.py / idb_walk.py)。
2. **CDP `IndexedDB.requestData` 在该 WhatsApp 版本返回 0 行** — 改经 Runtime.evaluate + 页面 JS (`indexedDB.open` + readonly `getAll`) 读取, 只取精简字段 (id/t/from/to)。
3. **chatId 归属** — IDB 消息无 `fromMe` 字段; `to` 恒为自身账号。规则: `our_jid = IDB 恒定 to`; chat 取"非自己"一方 (入站=from, 出站=to), 兼容引用回复。

实机验证结果 (打开一个会话跑 slow_tick): **9 条消息全部带正文入库, chatId 归属正确, 自动建 1 个客户 (对方)**。

### 已知限制 (MVP)
- 引用回复/相册等复合行: 正文可能混入引用文本, fromMe 偶有误判 (chat 归属不受影响)。
- 客户显示名 None / LID: 该版本聊天标识使用 LID (`@lid`), 部分客户以 LID 落库, 未做 LID↔手机号映射; 手机号为主标识, 名字可由 LLM 画像后续补充。
- 群聊消息 chat 归属未专门处理 (入站 from=成员 LID)。
- IDB 正文加密, 正文只能从 DOM 取 → 依赖"打开会话读取"。

### 新增: 自动扫描全部会话 (auto-scan)
- 实现 `Scanner.scan_all_chats()`: 逐个打开会话读取可见正文入库 (Playwright 原生可信 click, 不碰 CDP 输入, 保持只读门面)。
- 启动即执行首次全量扫描 (`run()` 首轮 `last_scan=-inf`), 之后按 `KB_AUTO_SCAN_INTERVAL_SEC`(默认 600s) 周期执行。
- 配置: `KB_AUTO_SCAN_CHATS` / `KB_AUTO_SCAN_INTERVAL_SEC` / `KB_AUTO_SCAN_MAX_CHATS`(默认100) / `KB_AUTO_SCAN_SETTLE_SEC`。
- ⚠️ 副作用: 打开会话会把未读消息标记为已读; 介意可设 `KB_AUTO_SCAN_CHATS=false`。
- 实测: 扫描 5 会话/45 条消息约 22s, 自动建 5 客户。
