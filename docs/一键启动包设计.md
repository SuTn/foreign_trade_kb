# 一键启动包设计文档

> 目标：让**不懂技术的个人外贸业务员**能"解压 → 双击 → 填 Key → 扫码登录 WhatsApp → 用"，无需安装 Python、无需命令行。
> 本文档供评审，评审通过后按模块实施。

> **v2 修订说明（2026-08）**：本版基于 `feature/20260815/cloud-embedding-rerank` 分支重写。
> 该分支已**彻底移除本地 embedding/rerank 模型，全切阿里云在线**（提交 `ce9809b`），
> 因此 v1 中关于 torch 打包、模型预下载、HF 镜像等章节**全部作废**，包体积从 ~1.5GB 降至 ~300MB。

---

## 一、背景与目标

### 1.1 现状痛点

当前系统需要业务员手动完成 5 步：

| # | 步骤 | 对业务员的难度 |
|---|------|----------------|
| 1 | 安装 Python 3.11+ | 🔴 大多数电脑没有 |
| 2 | 创建虚拟环境 + `pip install` | 🔴 命令行操作 |
| 3 | `playwright install chromium` | 🔴 又一条命令 + 下载 |
| 4 | 配置 `.env`（API Key 等） | 🟡 技术概念 |
| 5 | `python -m app` 启动 | 🔴 命令行 |

### 1.2 目标

- **业务员视角**：解压 → 双击 exe → 弹窗填 API Key → 点"保存并启动" → 浏览器自动打开 WhatsApp 扫码登录 → 完成。
- **开发者视角**：一条 `build.py` 命令产出可分发的 zip 包。

### 1.3 非目标

- 不做移动端 / 远程访问（本期聚焦本机一键启动）
- 不做自动更新（后续版本）
- 不做代码签名（成本高，后续按需）
- 不做 macOS / Linux（本期仅 Windows）

## 二、关键架构决策

### 决策 1：全在线 AI（已定，无需打包模型）✅

**背景**：v1 时代 embedding/reranker 走本地 bge 模型，依赖 torch（~2GB），是包体积的最大来源。

**现状（v2）**：`feature/20260815/cloud-embedding-rerank` 分支已全切阿里云在线：

| 能力 | 实现 | 依赖 |
|------|------|------|
| LLM 生成 | `CloudLLM`（anthropic/openai 兼容） | 纯 HTTP |
| Embedding | `OpenAIEmbedding` → 阿里云 `qwen3.7-text-embedding` | 纯 HTTP |
| Reranker | `CloudReranker` → 阿里云 `qwen3-rerank` | 纯 HTTP |

**结论**：`pyproject.toml` 已无 torch / FlagEmbedding / sentence-transformers。**打包不再需要任何模型文件，也不需要在首次启动时下载模型。** 业务员只需在配置向导里填一个阿里云 DashScope API Key（同时用于 embedding + reranker）和一个 LLM Key。

> 架构上已预留 `ollama` reranker 分支（OpenAI 兼容接口），但本期不打包本地模型。

### 决策 2：打包模式

```
PyInstaller --onedir（推荐）
  产出: 文件夹（exe + 依赖）
  启动: 快（无需解压）
  更新: 可只替换 app/ 代码文件夹增量更新

--onefile
  产出: 单个 exe
  启动: 慢（每次解压到临时目录）
  更新: 必须重新下整包
```

**推荐 `--onedir`**，打包成文件夹再 zip 分发。

### 决策 3：Chromium 打包策略

WhatsApp 采集依赖 Playwright 的 Chromium（约 150-200MB）。**推荐内嵌**：

- 打包时 `playwright install chromium` 到 `runtime/browsers/`
- 启动器设 `PLAYWRIGHT_BROWSERS_PATH` 指向内嵌目录
- 业务员解压即用，无需额外下载

> 备选：首次启动自动下载（包更小但体验差），本期不采用。

### 决策 4：包体积预估

| 组成 | 体积 |
|------|------|
| Python 3.11 + 依赖（fastapi/uvicorn/playwright/chromadb/pandas 等） | ~150MB |
| ChromaDB native 依赖（onnxruntime / pysqlite3） | ~50MB |
| Playwright Chromium | ~180MB |
| 项目代码 + 模板 + 静态资源 | ~5MB |
| **合计** | **~350-400MB** |

> 相比 v1 的 ~1.5GB（torch），体积下降约 75%。zip 压缩后约 150-200MB，网盘/微信可传。

## 四、模块设计

### 模块 1：启动器入口 `launcher/__main__.py`

exe 的入口，替代 `python -m app`，编排启动流程：

```python
def main():
    _setup_paths()          # 1. 修正 PyInstaller 打包后的资源路径
    _check_runtime()        # 2. 环境自检（磁盘空间/Chromium 就位）
    if not os.path.exists(".env"):
        run_wizard()        # 3. 首次配置向导（GUI 填 Key）
    start_tray()            # 4. 系统托盘（后台运行）
    _delayed_open_browser() # 5. 延迟打开浏览器（WhatsApp 登录页）
    app_main()              # 6. 复用 app/__main__.py 启动双进程
```

**关键点**：启动器不重写 `app/__main__.py` 逻辑，只包装一层，在调 `app_main()` 前做好环境准备。

**路径处理**（PyInstaller 打包后路径会变）：

```python
def _setup_paths():
    if getattr(sys, 'frozen', False):
        base = os.path.dirname(sys.executable)
        os.environ["PLAYWRIGHT_BROWSERS_PATH"] = os.path.join(base, "runtime", "browsers")
    else:
        base = os.path.dirname(os.path.abspath(__file__))
    os.chdir(base)
```

### 模块 2：首次配置向导 `launcher/first_run_wizard.py`

用 tkinter（标准库，无额外依赖）做 GUI：

```
┌─────────────────────────────────────────┐
│  外贸客户知识库 · 首次配置                │
│                                         │
│  LLM 服务:  [DeepSeek (推荐) ▾]         │
│  LLM API Key: [____________________]    │
│                                         │
│  阿里云 DashScope Key: [______________] │
│  （用于向量化 + 重排）                    │
│                                         │
│  [测试连接]        [保存并继续]          │
└─────────────────────────────────────────┘
```

- **LLM 服务商下拉**：DeepSeek（默认，推荐）/ OpenAI / Anthropic，选中自动填好 provider/model/base
  - DeepSeek 走 OpenAI 兼容接口：`KB_LLM_PROVIDER=openai`、`KB_LLM_API_BASE=https://api.deepseek.com/v1`、`KB_LLM_MODEL=deepseek-chat`
- **DashScope Key**：阿里云 API Key，同时用于 embedding + reranker（`KB_EMBEDDING_API_KEY` / `KB_RERANKER_API_KEY`）
- **"测试连接"按钮**：实际发一个最小 `chat.completions` + `embeddings` 请求验证两个 Key 有效
- **"保存并继续"**：写 `.env`，返回 True
- 生成的 `.env` 默认：`KB_EMBEDDING_PROVIDER=openai` + `KB_RERANKER_PROVIDER=aliyun`

### 模块 4：PyInstaller 配置 `build.spec`

处理所有动态导入（最耗时的部分）。**相比 v1，已无 torch，native 依赖只剩 ChromaDB**：

```python
# 完整收集 native 依赖（ChromaDB 是主要难点）
for pkg in ["chromadb", "onnxruntime", "pypdfium2", "openpyxl",
            "docx", "pandas", "bs4", "pydantic", "pydantic_settings"]:
    d, b, h = collect_all(pkg)
    datas += d; binaries += b; hiddenimports += h

# uvicorn 动态导入（PyInstaller 静态分析找不到）
hiddenimports += [
    "uvicorn.logging",
    "uvicorn.protocols.http.auto",
    "uvicorn.protocols.http.h11_impl",
    "uvicorn.protocols.websockets.auto",
    "uvicorn.protocols.websockets.wsproto_impl",
    "uvicorn.lifespan.on",
    "uvicorn.lifespan.off",
]

# FastAPI/Starlette 路由动态导入
hiddenimports += collect_submodules("fastapi")
hiddenimports += collect_submodules("starlette")
hiddenimports += collect_submodules("app")

# v2: 无 torch，无需 excludes
```

> ⚠️ ChromaDB 打包是本期最大风险点：其 `PersistentClient` 依赖 pysqlite3（自带 sqlite）与 onnxruntime（默认 embedding 用，虽本项目显式传 embedding_fn，但 import 链仍会加载）。需 `collect_all("chromadb")` + 实测。

## 五、打包前需要优化的现有代码（审计结论）

> 本节是**代码审计**产出。打包成 exe 后，开发环境"能用"的地方会变成致命问题。
> 以下按严重程度排序，**必须**在打包前处理。

### 🔴 P0：`app/__main__.py` 子进程启动方式（打包后必然崩溃）

```python
# app/__main__.py 第 12 行
proc = subprocess.Popen([sys.executable, "-m", "app.collector"])
```

**问题**：PyInstaller 打包后：
1. `sys.executable` 指向 exe 本身，**不是** Python 解释器
2. `-m app.collector` 依赖 Python 模块机制，PyInstaller 打包后**不存在**

**后果**：采集器子进程无法启动，整个系统瘫痪。

**方案**（三选一）：
- **A. 同进程内启动采集器**（推荐）：把 `_supervise()` 改为在进程内用 `asyncio` 跑采集器协程，去掉 subprocess。改动最小，但采集器崩溃无法自动重启。
- **B. PyInstaller 多进程模式**：用 `multiprocessing.freeze_support()` + 打包时把 collector 作为独立入口。需在 build.spec 里加 `multiprocessing` 支持，较复杂。
- **C. 双 exe**：打包两个 exe（主程序 + collector），主程序用 `subprocess.Popen([collector_exe])` 启动。改动小，但多一个 exe 文件。

> ⚠️ 这是**打包前必须解决**的问题，建议在 `start.bat` 阶段就验证方案 A 是否可行。

### 🟠 P1-`app/config.py` 相对路径依赖 `os.chdir`

```python
data_dir: Path = Path("data")   # 相对路径
```

**问题**：`data/`、`.env` 都是相对路径，依赖启动时 `os.chdir(base)`。若业务员从其他目录双击 exe（如快捷方式），相对路径会指向错误位置。

**方案**：启动器 `_setup_paths()` 里 `os.chdir(base)` 已处理。但需确保**所有**相对路径（`data/`、`.env`）都基于 `base` 解析，且 `base` 取 exe 所在目录（`os.path.dirname(sys.executable)`）。

### 🟠 P1：`app/web/app.py` 模板/静态文件路径

```python
base = Path(__file__).parent   # 定位 templates/ static/
```

**问题**：PyInstaller 打包后 `__file__` 指向 `_internal` 或临时解压目录（`sys._MEIPASS`），模板/静态文件需作为 **data 文件**收集，且运行时路径要改用 `sys._MEIPASS`。

**修复**：
- `build.spec` 里把 `app/web/templates/`、`app/web/static/` 加入 `datas`
- `app.py` 里用 `getattr(sys, '_MEIPASS', Path(__file__).parent)` 定位资源

### 🟠 P1：`sqlite_store.py` 的 `SCHEMA_PATH`

```python
SCHEMA_PATH = Path(__file__).parent / "schema.sql"
```

**问题**：`schema.sql` 是数据文件，PyInstaller 打包后 `__file__` 指向 `_internal`，需作为 data 收集。

**修复**：`build.spec` 把 `app/storage/schema.sql` 加入 `datas`，代码里用 `sys._MEIPASS` 定位。

### 🟡 P2：Python 3.13 兼容性

当前 venv 是 **Python 3.13.2**。PyInstaller 需 **6.11+** 才支持 3.13。打包前确认 PyInstaller 版本。

### 🟡 P2：chromadb 1.5.9 打包

当前装的是 **chromadb 1.5.9**（较新），其 native 依赖（onnxruntime 1.29.0、pysqlite3）打包行为需实测。`collect_all("chromadb")` 是必须的。

### 🟡 P2：openai 3.3.0 / langchain 1.3.15 大版本

当前 `openai` 是 **3.3.0**（v3 大版本）、`langchain` 是 **1.3.15**（v1）。这些大版本的 API 与文档假设的旧版不同，打包时需确认 `collect_submodules` 覆盖。

### 🟢 P3：配置向导需处理两个 Key

业务员需填 **DeepSeek Key**（LLM）+ **阿里云 DashScope Key**（embedding+reranker）。向导需：
- 默认 DeepSeek，自动填 `api_base=https://api.deepseek.com/v1`、`model=deepseek-chat`
- 阿里云 Key 同时写 `KB_EMBEDDING_API_KEY` 和 `KB_RERANKER_API_KEY`
- 两个 Key 都要"测试连接"

### 🟢 P3：`.env` 生成

向导生成的 `.env` 需包含：`KB_LLM_PROVIDER=openai`、`KB_LLM_API_BASE`、`KB_LLM_MODEL=deepseek-chat`、`KB_LLM_API_KEY`、`KB_EMBEDDING_PROVIDER=openai`、`KB_EMBEDDING_API_BASE`、`KB_EMBEDDING_API_KEY`、`KB_RERANKER_PROVIDER=aliyun`、`KB_RERANKER_API_BASE`、`KB_RERANKER_API_KEY`。

> ⚠️ 阿里云 embedding 和 reranker 的 `api_base` 格式不同（embedding 含 `/compatible-mode/v1`，reranker 不含），向导需分别处理。
